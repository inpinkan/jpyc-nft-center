# 自動分配への復帰（2.24.1 候補・本番未反映）

利用者の指定により、通常購入・オファー承諾・オークションの決済を旧 2.23.1 と同じ即時分配へ戻す。2.24.0 の手動引出しを新規売買の標準として継続しない。

## 動作

- 初回販売：販売代金の 95% を出品者、5% を運営へ決済と同時に送金する（自分の作品を自分で Mint する運用）。
- 再販：85% を出品者、10% を固定された Creator、5% を運営へ同時に送金する。
- 通常購入・オファー承諾・オークション即決は NFT の移転と自動分配を同一取引で完了する。
- オークション終了は従来どおり終了確定の取引が必要。その取引で落札者へ NFT を渡し、自動分配する。別途 NFT 受取り・売上引出しは不要。
- 入札なしの終了、オークション取消しは、その取引で NFT を出品者へ戻す。
- 追い越された入札の返金引出しは旧版と同じ方式を維持する。

Creator 確認、旧市場からの初回販売済み状態の参照、手数料の取引作成時固定、再入防止を維持する。

## 検証

`npm run test:automatic` はローカル EVM のみを使用する。12 項目合格。初回・再販の残高、運営自身による購入、オファー、終了確定・即決・取消し・入札なし、送金拒否時の全体巻戻し、再入防止、旧販売状態、他の預り金の保全を検証した。Solidity 0.8.24、optimizer 200、Shanghai。runtime 17,754 bytes。

自動分配には旧版と同じ制約がある。送金を拒否される受取先や NFT を拒否する落札者があると、決済全体が失敗する。その条件が解消するまでオークション終了が進まない可能性が残る。手動引出しへ黙って切り替える処理は入れていない。

## 本番切替に必要な作業

現在の Polygon / BNB の 2.24.0 は書換え不能であり、このソース修正だけでは動作は変わらない。

1. 2.24.1 を新規配置する。直前の 2.24.0 と、それ以前の市場を履歴参照先に含める。
2. Creator と初回販売状態を新契約で検証・登録し、決済トークン、最低価格、入札増分、運営アドレスを現行設定と照合する。
3. 画面のバージョン照合・実行コードハッシュ照合・決済案内を 2.24.1 に対応させる。旧 2.24.0 の引出し・NFT 受取画面は既存権利のため残す。
4. 現在の出品を再取得し、売主が新市場への承認と再出品を行う。既存の承認・出品を別契約へ自動コピーすることはできない。価格は現行出品を引き継ぐ。購入済み NFT #15 は新所有者の判断で再出品する。
5. 切替後の購入・分配・表示を確認して公開設定を切り替える。

再配置前に、2.24.0 を参照する公開画面の設定だけを変更しない。旧 2.24.0 ソースは配置済みコードの検証と残存権利の確認に必要であり、不要コードとして削除しない。

今回の試験購入 500 JPYC は、利用者の提示した記録では売主 425、Creator 50、運営 25 の引出し済み。新契約へ移すための送金は不要。
